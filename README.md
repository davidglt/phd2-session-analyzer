# PHD2 Session Analyzer

Python tools for analysing PHD2 guiding sessions, dither commands, settling
behaviour, guide-frame telemetry, sky-condition indicators, and guiding
configuration.

The project reads PHD2 guide logs, identifies individual dithers, measures
their recovery behaviour, and produces a human-readable report plus a CSV file
for each analysed session.

## Features

- Parses PHD2 guide logs generated by PHD2 2.x.
- Supports both `INFO DITHER by` and `INFO: DITHER by` log formats.
- Detects `Settling complete` and `Settling failed` outcomes.
- Extracts guiding-session configuration:
  - Equipment profile
  - Mount
  - Guide camera
  - Guide exposure
  - Guide focal length
  - Pixel scale
  - Dither axes and scale
  - RA and DEC guiding algorithms
  - RA hysteresis, aggression, and minimum move
  - DEC aggression, minimum move, and backlash-compensation state
- Extracts PHD2 guide-frame CSV telemetry:
  - Raw RA and DEC errors
  - Final total error
  - Star mass
  - Signal-to-noise ratio (SNR)
  - Error code
- Calculates per-dither metrics:
  - RA and DEC dither offsets
  - Dither magnitude in pixels and arcseconds
  - Estimated settling duration
  - Final RA, DEC, and total error
  - Initial, mean, minimum, and final SNR
  - SNR drop percentage
  - Dropped guide-frame count
  - Guide-star loss count
  - Possible cloud or transparency indicator
- Estimates a settling-timeout candidate from failed dither durations.
- Flags failed dithers that finish close to the inferred timeout.
- Writes one plain-text report and one CSV file per analysed session.
- Stores generated results in a local `reports/` directory.

## Requirements

- Python 3.10 or later.
- PHD2 guide logs enabled.
- No third-party Python packages are required.

## Installation

Clone the repository:

```bat
git clone https://github.com/davidglt/phd2-session-analyzer.git
cd phd2-session-analyzer
```

Create and activate a virtual environment if desired:

```bat
py -m venv .venv
.venv\Scripts\activate
```

The analyzer only uses the Python standard library, so no package installation
is required.

## Configuration

Create or edit `phd2_dither_analyzer.properties` beside the Python script:

```properties
# PHD2 Session Analyzer configuration
#
# The value may be:
# - A directory containing PHD2 guide logs.
# - A single PHD2 guide-log file.
# - A glob pattern matching one or more guide logs.
#
# When multiple files match, the analyzer selects the newest log that contains
# guiding activity or a recognized PHD2 dither command.

phd2.logs.path=C:/Users/davidglt/Documents/PHD2/*GuideLog*.txt
```

Forward slashes are recommended in the properties file, including on Windows.

## Usage

Run with the default configuration file:

```bat
python phd2_dither_analyzer.py
```

Run with another properties file:

```bat
python phd2_dither_analyzer.py path/to/phd2_dither_analyzer.properties
```

## Output files

The analyzer creates the following directory automatically:

```text
reports/
```

For every analysed guide log, it writes:

```text
reports/
├─ PHD2_GuideLog_YYYY-MM-DD_HHMMSS_dither_report.txt
└─ PHD2_GuideLog_YYYY-MM-DD_HHMMSS_dithers.csv
```

The generated `reports/` directory is intended for local session history and
should be ignored by Git:

```gitignore
# Generated PHD2 analysis reports
/reports/
```

### Text report

The report includes:

- Guiding-session configuration.
- Total, complete, failed, and unresolved dither counts.
- One table row per dither.
- Inferred settling-timeout candidate.
- Final RA/DEC errors.
- Mean and minimum SNR values.
- Dropped-frame and guide-star-loss information.
- Conservative sky-condition indicators.
- Operational conclusions and recommendations.

## Interpretation

### Settling timeout

The analyzer derives an **inferred settling timeout candidate** from the median
duration of failed dithers. This is not a direct reading of SharpCap or PHD2
configuration.

When many failures cluster around the inferred timeout, the report identifies
this pattern. It commonly indicates that the imaging application exhausted its
configured maximum settle time.

For example, if most failed dithers end near 56–60 seconds and the imaging
application uses a 60-second maximum settle time, the failure pattern is
consistent with a timeout rather than immediate guide-star loss.

### Sky-condition indicators

The `sky condition` field is intentionally conservative:

| Value | Meaning |
|---|---|
| `clear` | No significant SNR drop, dropped frame, or guide-star loss was detected. |
| `possible cloud` | The minimum SNR dropped by at least 30% from the initial SNR. |
| `likely cloud` | The SNR dropped by at least 50%, or one or more dropped guide frames occurred. |
| `star lost` | A guide-star loss message occurred during the dither block. |
| `insufficient data` | There was not enough SNR information to classify the dither. |

These labels do not prove cloud coverage. Low SNR can also result from haze,
dew, focus changes, seeing, star contamination, camera noise, or other
conditions.

### Final guiding error

`final RA`, `final DEC`, and `final err` describe the final raw guide-frame
error observed before PHD2 reported the settling outcome.

A failed dither with stable SNR and large final error is more consistent with
slow mount recovery, backlash, mechanical stiction, balance, cable drag, or a
too-short settling timeout than with a cloud-related guide-star problem.

## Recommended workflow

1. Start PHD2 and begin guiding normally.
2. Run the imaging sequence with dithering enabled in SharpCap.
3. After the session, run:

   ```bat
   python phd2_dither_analyzer.py
   ```

4. Review the generated report in `reports/`.
5. Compare:
   - Complete and failed dither counts.
   - Inferred timeout.
   - Settling durations.
   - Final RA/DEC errors.
   - SNR and cloud indicators.
6. Keep one significant configuration change per session when testing:
   - Guide-camera exposure.
   - Dither size.
   - Maximum settle time.
   - Settle threshold.
   - RA or DEC guiding parameters.

## Example tuning workflow

For a configuration using a 50ED guide scope, ASI224MC guide camera, and
dithering through SharpCap:

1. Establish a baseline session.
2. Use the report to identify whether failed dithers:
   - cluster around a timeout;
   - retain good SNR;
   - lose the guide star;
   - end with predominantly RA or DEC error.
3. If failures cluster near the timeout with healthy SNR:
   - increase the maximum settle time;
   - reduce dither amplitude modestly;
   - inspect mount balance, backlash, cable routing, and mechanical motion.
4. If failures are associated with SNR drops, `DROP` frames, or star loss:
   - investigate cloud, haze, dew, guide-star selection, focus, and guide
     exposure.
5. Re-run the analyzer after each session and compare the reports.
